🔴 El Problema: CLIENTE vs CONTACTO

⚠️ LA CONFUSIÓN

El usuario dice: "Ambos se registran con DNI y RUC. ¿Cómo los diferencio?"

La respuesta: Sí, ambos tienen DNI y RUC, pero son CONCEPTOS DIFERENTES.

Aquí está la claridad:

🏢 CLIENTE (la entidad que cotiza)

Definición: La entidad FINAL que pide la cotización.

Puede ser:

  • Una EMPRESA (tiene RUC)
  • Una PERSONA (tiene DNI)

Ejemplo:

La empresa "Constructora ABC" (RUC 20123456789) pide una cotización.

👥 CONTACTO (la persona que firma/acepta)

Definición: La PERSONA que representa al cliente.

Siempre es: Una persona con DNI

Relación: Trabajar en una empresa cliente

Ejemplo:

Juan García (DNI 12345678) es gerente de "Constructora ABC".

💡 Ejemplo Práctico Completo

Escenario: Necesitas entender exactamente qué es qué.

Caso 1: Cliente Empresa (RUC)

CLIENTE = Constructora ABC (RUC 20123456789) ├─ Razón Social: Constructora ABC S.A.C. ├─ Dirección: Av. Principal 123 └─ Estado: Activa CONTACTO = Juan García (DNI 12345678) ├─ Vinculado a RUC: 20123456789 ├─ Cargo: Gerente de Proyectos ├─ Celular: +51912345678 └─ Email: juan@abc.com COTIZACIÓN: Solicitada por: Juan García (representa a Constructora ABC) A nombre de: Constructora ABC Para proyecto: Torre 2024

Caso 2: Cliente Persona (DNI)

CLIENTE = Juan García (DNI 12345678) ├─ Nombre: Juan ├─ Apellido: García ├─ Celular: +51912345678 └─ Empresa: Constructora ABC (opcional) CONTACTO = NO EXISTE en este caso (Porque Juan es el cliente directo, no un contacto) COTIZACIÓN: Solicitada por: Juan García (como persona individual) A nombre de: Juan García Para proyecto: Torre 2024

Caso 3: Cliente Empresa, Múltiples Contactos

CLIENTE = Constructora ABC (RUC 20123456789) CONTACTO 1 = Juan García (DNI 12345678) ├─ Cargo: Gerente de Proyectos └─ Celular: +51912345678 CONTACTO 2 = María López (DNI 87654321) ├─ Cargo: Coordinadora Técnica └─ Celular: +51987654321 COTIZACIÓN 1: Solicitada por: Juan García A nombre de: Constructora ABC COTIZACIÓN 2 (mismo cliente, otro contacto): Solicitada por: María López A nombre de: Constructora ABC
💡 Clave: Un RUC puede tener MÚLTIPLES contactos (DNI). Cada cotización se vincula al cliente (RUC o DNI) y al contacto específico (DNI) si aplica.

📊 Diagrama Entidad-Relación

🔄 Flujo Completo: Cómo el Usuario Crea una Cotización

1 Usuario abre pantalla 1
Elige si cotiza por RUC (empresa) o DNI (persona)
2 Si selecciona RUC
Sistema busca en EMPRESAS y autocompleta razonSocial. Sistema busca CONTACTOS vinculados a ese RUC y muestra dropdown. Usuario elige contacto (o agrega uno nuevo). Se crea registro en COTIZACIONES con clienteRuc + contactoId
3 Si selecciona DNI
Sistema busca en PERSONAS y autocompleta nombre/apellido. Usuario puede indicar si trabaja en alguna empresa. Se crea registro en COTIZACIONES con clienteDni (contactoId = null)
4 Usuario llena proyecto + validez
Estos datos se guardan en COTIZACIONES.proyecto y COTIZACIONES.validezDias
5 Pantalla 2: Añade ensayos/paquetes
Usuario busca en ENSAYOS_CATALOGO y PAQUETES_CATALOGO Especifica cantidad Se crea múltiples registros en COTIZACION_ITEMS (uno por línea)
6 Sistema calcula subtotales
Para cada ITEM: cantidad × precioUnitario = subtotal
7 Pantalla 3: Aplica descuentos
Usuario selecciona tipo (% o monto) y valor Se crea registro en DESCUENTOS con cotizacionId Sistema calcula: SUBTOTAL - descuento = NETO
8 Sistema calcula IGV
NETO × 1.18 = TOTAL FINAL
9 Pantalla 4: Envía cotización
Usuario descarga PDF, comparte por WhatsApp, o envía email Se actualiza COTIZACIONES.estado = "enviada" TODA la información se mantiene registrada en BD para futuras referencias

⚙️ Reglas de Negocio Importantes

1. Cliente (COTIZACIONES)

  • Un cliente DEBE ser RUC O DNI (no puede ser ninguno de los dos = error)
  • Si es RUC → clienteRuc = obligatorio, clienteDni = NULL
  • Si es DNI → clienteDni = obligatorio, clienteRuc = NULL
  • Un RUC NO puede tener dos cotizaciones simultáneamente (una es la actual, otras terminadas)

2. Contacto (vinculado a COTIZACIONES)

  • contactoId solo se llena si clienteRuc está lleno
  • Si clienteDni está lleno → contactoId siempre es NULL
  • Un RUC puede tener múltiples contactos, pero cada cotización tiene UN contacto

3. Ensayos/Paquetes

  • El usuario SOLO puede seleccionar de ENSAYOS_CATALOGO y PAQUETES_CATALOGO (no crear en el momento)
  • Los precios son fijos (lo define el laboratorio, no el usuario)
  • Una cotización puede mezclar ensayos y paquetes en las mismas líneas

4. Descuentos

  • Una cotización puede tener 0 o 1 descuento (no múltiples descuentos)
  • Si es porcentaje: se aplica al subtotal total
  • Si es monto: es un valor fijo en S/.

5. Cálculos

  • IGV siempre es 18% (fijo por ley Perú)
  • IGV se aplica DESPUÉS del descuento
  • Todos los montos en soles (S/.)

✅ Resumen Ejecutivo

  • 8 tablas normalizadas interconectadas por Foreign Keys
  • CLIENTE = RUC (empresa) O DNI (persona) - NUNCA ambos en una cotización
  • CONTACTO = Persona que trabaja en empresa - Solo existe si cliente es RUC
  • Cada cotización guarda cliente, items, descuentos e histórico completo
  • El usuario NO crea ensayos/paquetes - Solo selecciona del catálogo y ajusta cantidad
  • Sistema calcula automáticamente subtotales, descuentos e IGV
